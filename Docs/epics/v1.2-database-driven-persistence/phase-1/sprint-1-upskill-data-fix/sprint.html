Sprint 1: Upskill Data Fix

Phase: 1 Sprint: 1 Depends on: Sprint 0 (Scraper Skill Update)

Objective

Fix the upskill skill's broken data pipeline. Currently it reads from job_search_tracker.csv (empty — 0 rows) while the real job data sits in seen_jobs.json (71 jobs). Switch the data source to the database, fix the fit_rating semantics mismatch (enum vs. 0–100 numeric), and ensure the upskill workflow can actually produce meaningful skill gap analyses.

Rationale & Context

The upskill skill (.opencode/skills/upskill/SKILL.md) has two modes: aggregate (all tracked jobs) and targeted (a single URL). Both are currently broken in different ways:

  • Aggregate mode: Reads job_search_tracker.csv which has zero data rows. The real job data (71 entries with descriptions, fit ratings, and skills) is in seen_jobs.json, but the upskill skill never reads that file. Result: aggregate mode always produces an empty heatmap.
  • fit_rating semantics: The upskill spec says fit_rating is a numeric 0–100 column, but the actual data uses string enums: high, medium, low, unrated. The weighting formula (100 - fit_rating) / 100 would error on string values.
  • Targeted mode: WebFetches a single URL — this works independently of the tracker, but still uses the wrong fit_rating semantics.

With the unified database, both issues are resolved:

  • Aggregate mode queries python3 db/client.py jobs list --status applied --status evaluated — returning actual job data with full descriptions.
  • The new evaluation_score column (0–100) is the correct numeric field for weighting. For jobs without an evaluation score, fit_rating maps to a default: high=80, medium=50, low=20, unrated=50.
  • Targeted mode remains unchanged (WebFetch-based), but the report now saves to the standard upskill/ directory alongside data-driven reports.

Execution Plan

  1. Task 4.1: Add GET /jobs/skills/aggregate endpoint

    New endpoint that accepts optional ?status=applied&status=evaluated query params and returns a skill frequency map across matching jobs. The endpoint:

    • Queries SELECT id, title, company, description_text, evaluation_score, fit_rating FROM jobs WHERE status IN (...)
    • For each job, returns the raw data — the LLM (upskill skill) extracts skills from descriptions, this endpoint just provides the data efficiently
    • Returns a JSON array of job summaries: [{"id": 1, "title": "...", "company": "...", "description_text": "...", "evaluation_score": null, "fit_rating": "high"}, ...]
    • Weighting and skill extraction remain the LLM's responsibility (Pass 1 pass in the upskill methodology)
  2. Task 4.2: Add "skills aggregate" subcommand to client.py

    python3 db/client.py skills aggregate [--status applied] [--status evaluated] → calls GET /jobs/skills/aggregate?status=applied&status=evaluated and prints the JSON array.

  3. Task 4.3: Rewrite upskill SKILL.md — Mode section

    Update lines 12–13 (aggregate mode) and lines 15–16 (profile loading):

    • Replace job_search_tracker.csv reference with database query
    • Fix fit_rating semantics: document the enum-to-numeric mapping
    • Profile loading (01-candidate-profile.md) is unchanged
  4. Task 4.4: Rewrite upskill SKILL.md — Pass 1 section

    Update lines 21–25 (hard skill diff):

    • Data source: python3 db/client.py skills aggregate --status applied --status evaluated instead of CSV parsing
    • Skill inference: from description_text and title fields (not CSV columns)
    • Weighting: use evaluation_score with fit_rating fallback formula
    • Diff against profile: unchanged logic
  5. Task 4.5: Verify upskill produces non-empty results

    After migration (71 jobs in DB) and at least one job marked as evaluated:

    • Run upskill in aggregate mode: the skill should query the DB and find jobs
    • Verify the Gap Heatmap has actual entries (not "No tracked jobs found")
    • Verify the Learning Plan has actual study resources (found via WebFetch)
    • Verify the report saves to upskill/report-YYYY-MM-DD.md

Verification & Acceptance Criteria

  • The word "job_search_tracker.csv" appears zero times in the upskill SKILL.md

  • Aggregate mode queries the database, not a CSV file
