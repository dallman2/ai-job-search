Sprint 0: Scraper Skill Update

Phase: 1 Sprint: 0 Depends on: Phase 0 (Infrastructure & Data Layer), v1.1 Sprint 3 (Indeed Integration)

Objective

Replace all references to seen_jobs.json and job_search_tracker.csv in the scraper skill with db/client.py API calls. Every read, write, update, and dedup check that currently manipulates flat files must go through the database. At the end of this sprint, "scrape jobs fast" stores results in the database, deduplicates against the database, and never touches a JSON file.

Rationale & Context

The scraper SKILL.md (.opencode/skills/job-scraper/SKILL.md) has approximately 25 references to seen_jobs.json and job_search_tracker.csv across four major sections: State, Search/Dedup, Evaluation Handoff, and Application Tracking. Each reference needs a corresponding db/client.py command.

The changes are mechanical replacements, not architectural rewrites. The scraper's logic (board-list navigation, CDP searches, rapid scoring, dedup, output formatting) remains identical. Only the persistence layer changes. However, the output format must also adapt: job IDs are now database row IDs (integers), not composite dictionary keys.

The db/client.py CLI was designed specifically to make these replacements clean: each JSON operation maps to a single subcommand with --flag arguments that read naturally in the skill instructions.

Execution Plan

  1. Task 3.1: Add --since parameter to GET /jobs and client.py

    The "new" mode filter requires the DB layer to accept a ?since=ISO_TIMESTAMP query param that filters first_seen > since. This is needed before the SKILL.md can reference it. Add to both main.py (server) and client.py (CLI).

  2. Task 3.2: Rewrite SKILL.md State section (lines 13–24)

    Replace the first two bullets under "State" with:

    • Before searching, verify the SQLite API is reachable: python3 db/client.py health. If unreachable, report: "SQLite API not reachable at localhost:30080. Start the kind cluster with: bash db/start-cluster.sh". Abort the scrape.
    • Load current state: python3 db/client.py stats for aggregate counts, python3 db/client.py scrape-runs list --limit 1 for last run timestamp (if "new" mode).

    Remove references to seen_jobs.json creation (if missing), job_search_tracker.csv loading, and the composite dedup key construction from JSON dict keys.

  3. Task 3.3: Rewrite SKILL.md Search/Dedup/Insert sections (lines 84–88, 140–170)

    Replace pre-filter logic: instead of checking seen_jobs.json dict keys, use:

    python3 db/client.py jobs check --dedup-key "anthropic_product-engineer"

    Replace insert logic: instead of the dict assignment (seen[key] = {"title": ..., ...}), use:

    python3 db/client.py jobs insert '{"title":"...", "company":"Anthropic", ...}'

    If the command exits with a non-zero status (409 Conflict), the job is a duplicate — skip it.

    Replace run tracking: instead of seen_jobs.json mutation, use:

    python3 db/client.py scrape-runs log '{"mode":"fast", ...}'
  4. Task 3.4: Rewrite SKILL.md Output section (lines 180–217)

    Replace the output generation logic:

    • Summary line: counts come from python3 db/client.py stats (run after inserting new jobs to get fresh counts)
    • Ranked table: python3 db/client.py jobs list --status new --fit-rating high --limit 50 and python3 db/client.py jobs list --status new --fit-rating medium --limit 50
    • Table columns: | # | Fit | Title | Company | Location | Key Match | — unchanged format, but the # column is now the database id (not an ordinal position in a dict)
  5. Task 3.5: Rewrite SKILL.md Evaluation Handoff section (lines 219–240)

    Replace the "look up entry in seen_jobs.json" instruction:

    • User picks a number (the database id)
    • Load the job: python3 db/client.py jobs get <id>
    • If description_md is truncated or empty, re-fetch via browser_markdown and update: python3 db/client.py jobs update <id> --description-md "..." --description-text "..."
    • After evaluation: python3 db/client.py jobs update <id> --status evaluated --evaluation-score <score>
  6. Task 3.6: Rewrite SKILL.md Application Tracking section (lines 232–251)

    Replace the CSV append:

    • After user confirms application submission: python3 db/client.py jobs update <id> --status applied --applied-date "YYYY-MM-DD" --notes "CV: applications/company/resume.md, CL: applications/company/cover_letter.md"
    • Remove all references to job_search_tracker.csv
  7. Task 3.7: Add --api-url flag to cdp_search.py

    Add an optional --api-url argument that, when provided, causes the script to POST each result to the DB after extraction. If the API is unreachable or returns errors, fall back to stdout JSON output (current behavior). Update the CLI help text to document this flag.

    This flag applies to all subcommands: linkedin, wellfound, and indeed (added in v1.1 Sprint 3). The implementation goes in the shared argument parser or base function, not duplicated per subcommand.

    This is a convenience feature: the scraper can still collect JSON output and insert separately. The flag just eliminates one round-trip for the AI assistant.

  8. Task 3.8: Update opencode.json with infrastructure note

    Add to the instructions array or as a comment in OPENDOC.md: "Before scraping jobs, ensure the SQLite API is running: bash db/start-cluster.sh. Verify: python3 db/client.py health."

    Optionally add a POST /jobs webhook-like pattern to the permission block if needed.
