Sprint 0: SQLite API Container

Phase: 0 Sprint: 0 Depends on: —

Objective

Build a Docker container that wraps SQLite behind a FastAPI HTTP interface. Define the database schema in schema.sql (unified jobs table, scrape_runs, job_skills, FTS5 index). Implement CRUD endpoints for jobs and scrape runs, plus full-text search and aggregate stats. Build db/client.py — a zero-dependency CLI that the AI assistant uses to interact with the API. Test locally with docker run before moving to kind.

Rationale & Context

SQLite is an embedded database — it has no network protocol. To run it as a "database container" accessible from other processes (the AI assistant, cdp_search.py, the upskill analysis), we need a thin HTTP wrapper. FastAPI is ideal: mature, fast, and the Python sqlite3 module is in the standard library, so the only pip dependencies are fastapi and uvicorn.

The db/client.py CLI is the bridge between the AI assistant and the API. Rather than teaching the assistant to construct curl commands (which requires escaping JSON, handling HTTP errors, etc.), the CLI provides subcommands with standard --flag arguments. It uses only Python stdlib (urllib.request, json, argparse) so it runs anywhere Python 3 is installed.

The schema is designed to be a strict superset of the existing data: every field from seen_jobs.json plus the job_search_tracker.csv columns (applied_date, notes) are folded into a single jobs table. New columns (evaluation_score, description_text) are added for future use. FTS5 provides full-text search with automatic trigger-based index maintenance.

Execution Plan

1. Write the Database Schema

  1. Task 0.1: Write schema.sql

    Create the full DDL. Key design points:

    • jobs.url has a UNIQUE constraint — this is the primary dedup mechanism
    • jobs.dedup_key stores the normalized company+title for fallback dedup (constructed during insert)
    • jobs.fit_rating has a CHECK constraint on the four valid enum values
    • jobs.status has a CHECK constraint on the four lifecycle states
    • jobs_fts is a content-sync FTS5 table referencing jobs
    • Three triggers (jobs_ai, jobs_ad, jobs_au) keep FTS5 in sync
    • job_skills has a composite PK and CASCADE delete on the FK
    • All CREATE statements use IF NOT EXISTS for idempotent startup

2. Build the FastAPI Server

  1. Task 0.2: Write main.py — app structure and DB connection

    FastAPI app with:

    • get_db() context manager: sqlite3.connect(DB_PATH), row_factory = sqlite3.Row, PRAGMA journal_mode=WAL, PRAGMA foreign_keys=ON. Commit on success, rollback on exception.
    • DB_PATH from os.environ.get("DB_PATH", "/data/job-search.db")
    • @app.on_event("startup") — if DB_PATH doesn't exist, run schema.sql
    • Pydantic models: JobCreate, JobUpdate, ScrapeRunCreate
  2. Task 0.3: Implement endpoints — Health and Stats
    • GET /health → {"status": "ok", "db": "/data/job-search.db"}
    • GET /stats → aggregate counts: total jobs, by status, by fit_rating, by source, by company (top 10). Uses sqlite3.Row → dict conversion.
  3. Task 0.4: Implement endpoints — Jobs CRUD
    • GET /jobs?status=new&fit_rating=high&source=linkedin&company=Anthropic&limit=50&offset=0 → build WHERE clause dynamically from query params. Map to list of dicts.
    • GET /jobs/{id} → single job with full description_md
    • POST /jobs → insert new job. Auto-set created_at, last_updated. Return 409 Conflict if url already exists. Auto-generate dedup_key from normalized company+title.
    • PUT /jobs/{id} → partial update. Only update fields present in the JSON body. Auto-update last_updated. Return 404 if not found.
    • GET /jobs/check?url=...&dedup_key=... → lightweight dedup probe. Returns {"exists": true/false, "job": {...}} or {"exists": false}.
  4. Task 0.5: Implement endpoints — FTS5 Search and Scrape Runs
    • GET /jobs/search?q=kubernetes+agentic&limit=20 → FTS5 MATCH query against jobs_fts. Returns ranked results with snippets via snippet().
    • GET /scrape-runs?limit=10 → list recent runs, newest first
    • POST /scrape-runs → log a new scrape run. Auto-set created_at.

3. Build the CLI Client

  1. Task 0.6: Write client.py — subcommand structure and helpers

    CLI with argparse subcommands:

    • health → GET /health, print JSON
    • jobs list [--status STATUS] [--fit-rating RATING] [--source SRC] [--company NAME] [--limit N] [--offset N] → GET /jobs with query params
    • jobs get ID → GET /jobs/{id}, print JSON with description_md
    • jobs search --q "text" [--limit N] → GET /jobs/search
    • jobs insert '{"url": "...", "title": "...", ...}' → POST /jobs with JSON body from string
    • jobs update ID [--status STATUS] [--fit-rating RATING] [--applied-date DATE] [--notes NOTES] [--evaluation-score N] → PUT /jobs/{id} with partial update
    • jobs check [--url URL] [--dedup-key KEY] → GET /jobs/check
    • scrape-runs list [--limit N] → GET /scrape-runs
    • scrape-runs log '{"mode": "fast", ...}' → POST /scrape-runs
    • stats → GET /stats, pretty-print as table

    Helper functions: _api_url(path) constructs the full URL from --api-url or API_URL env var. _get(path) / _post(path, data) / _put(path, data) use urllib.request with error handling (print HTTP status + body on error, exit 1).

4. Containerize

  1. Task 0.7: Write Dockerfile and requirements.txt 
    FROM python:3.12-slim
WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY main.py schema.sql ./
RUN mkdir -p /data
EXPOSE 8000
ENV DB_PATH=/data/job-search.db
CMD ["uvicorn", "main:app", "--host", "0.0.0.0", "--port", "8000"]
  2. Task 0.8: Build Docker image and smoke test locally

    docker build -t job-search-db:latest db/

    docker run -d --name job-search-db-test -p 8000:8000 -v $(pwd)/data:/data job-search-db:latest

    Verify:

    • curl localhost:8000/health → {"status": "ok"}
    • curl localhost:8000/stats → {"total_jobs": 0, ...}
    • curl -X POST localhost:8000/jobs -H 'Content-Type: application/json' -d '{"url":"https://test.example/job/1","title":"Test Job","company":"TestCo","first_seen":"2026-06-09T00:00:00Z","last_updated":"2026-06-09T00:00:00Z","dedup_key":"testco_test-job"}' → {"id": 1, ...}
    • curl localhost:8000/jobs/1 → returns the inserted job
    • curl -X POST localhost:8000/jobs -H 'Content-Type: application/json' -d '{"url":"https://test.example/job/1",...}' → HTTP 409 Conflict
    • curl "localhost:8000/jobs/search?q=test" → returns the job
    • docker stop job-search-db-test && docker rm job-search-db-test

Verification & Acceptance Criteria

  • docker build -t job-search-db db/ succeeds without errors
  • Container starts and /health returns {"status": "ok"}
  • schema.sql auto-runs on first start; subsequent restarts are idempotent (no duplicate table errors)
  • POST /jobs inserts a record and returns it with auto-generated id, created_at, dedup_key
  • POST /jobs with duplicate URL returns HTTP 409 with clear error message
  • PUT /jobs/{id} performs partial update (only provided fields change); last_updated auto-refreshes
  • GET /jobs/search?q=keyword returns FTS5 matches ranked by relevance
  • GET /stats returns accurate aggregate counts across all dimensions
  • POST /scrape-runs logs a run; GET /scrape-runs lists them newest-first
  • db/client.py health works from any directory with zero pip installs
  • db/client.py jobs insert '{"url": "...", ...}' works with JSON string argument
  • db/client.py stats prints a readable aggregate table
  • DB file persists on host via volume mount; container restart does not lose data
