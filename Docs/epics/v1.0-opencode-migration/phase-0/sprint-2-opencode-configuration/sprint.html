Sprint 2: opencode.json Configuration

Phase: 0 Sprint: 2 Depends on: Sprint 0

Objective

Create the opencode.json configuration file that defines tool permissions, registers all 7 skills, and defines 2 subagent stubs (reviewer and research-expert). This replaces .claude/settings.local.json and the allowed-tools frontmatter that was stripped in Sprint 1. Full subagent system prompts will be written in Phase 1; this sprint creates the configuration shell with stub prompts.

Rationale & Context

opencode centralizes all configuration in opencode.json at the repo root. This is the single source of truth for:

  • Permissions: which tools and Bash commands the model is allowed to use (replaces per-skill allowed-tools)
  • Skill registration: which skills are available for the skill tool to load (replaces Claude Code's implicit directory-based discovery)
  • Subagent definitions: named agents with system prompts, tool access, and model configurations (replaces .claude/agents/ and ad-hoc inline prompt construction)

The old .claude/settings.local.json was a simple allowlist: "allow Skill(job-application-assistant), Bash(python3:*), Bash(python:*), Bash(curl:*), Bash(bun:*)." The new opencode.json does the same job but also registers all 7 skills and defines the 2 subagents that the workflow dispatches.

This sprint must study opencode's configuration schema before writing. Caroline's .opencode/ directory contains working examples of how opencode agents and skills are configured.

Scope

Execution Plan

1. Research opencode Configuration Schema

  1. Task 2.1: Fetch opencode configuration documentation

    Use WebFetch to retrieve opencode's configuration schema from https://opencode.ai or the opencode GitHub repository. Document the JSON structure for: permissions, skills registration, subagents/agents, instructions. Note any differences from Claude Code's model.

  2. Task 2.2: Study caroline's opencode configuration

    Read caroline's .opencode/ directory structure and any opencode.json or equivalent config files. Extract the working pattern for: (a) how skills are registered, (b) how subagents are defined with system prompts and tool access, (c) how permissions are structured. Use this as the template for our config.

2. Permissions Block

  1. Task 2.3: Define tool permissions

    Write the permissions block allowing all tools the workflow needs:

    • Bash: python3:*, python:* (salary lookup tool), bun:* (CLI job search tools), lualatex:* (CV compilation), xelatex:* (cover letter compilation), curl:* (web requests if needed)
    • File operations: Read, Write, Edit, Glob, Grep (all standard file operations)
    • Web operations: WebFetch (job posting retrieval, company research)
    • Agent operations: Task (subagent dispatch), Question (user prompts)

    Use the format from opencode's schema, not Claude Code's settings.local.json format.

3. Skill Registration

  1. Task 2.4: Register all 7 skills

    Register the skills so opencode's skill tool can load them:

    • .opencode/skills/job-application-assistant/ — core application workflow
    • .opencode/skills/job-scraper/ — job search orchestration
    • .opencode/skills/upskill/ — skill gap analysis
    • .agents/skills/jobindex-search/ — Jobindex.dk CLI
    • .agents/skills/jobbank-search/ — Jobbank.dk CLI
    • .agents/skills/jobnet-search/ — Jobnet.dk CLI
    • .agents/skills/jobdanmark-search/ — Jobdanmark.dk CLI

    Note: the 4 CLI skills are already recognized by opencode (they appear in the available_skills system prompt list). Registration in opencode.json may be optional for these, but include them for completeness.

4. Subagent Definitions (Stubs)

  1. Task 2.5: Define reviewer subagent stub

    Define the reviewer subagent with a stub system prompt and read-only tool access. The full prompt will be written in Phase 1 Sprint 4. For now:

    • Name: reviewer
    • Description: "Reviews job application drafts for targeting, missed keywords, company alignment, tone, and factual accuracy."
    • Tools: Read, WebFetch (read-only — no Write/Bash)
    • System prompt: Placeholder indicating the full prompt arrives in Phase 1
  2. Task 2.6: Define research-expert subagent stub

    Define the research-expert subagent stub. The old agent used a gemini CLI tool that may not exist in opencode; the new version will use WebFetch:

    • Name: research-expert
    • Description: "Researches companies, technologies, and market context for job applications."
    • Tools: WebFetch, Read
    • System prompt: Placeholder indicating the full prompt arrives in Phase 1

5. System Instructions

  1. Task 2.7: Set up system instructions (if opencode supports it)

    If opencode supports a system instructions file or directory (analogous to Claude Code's auto-loading of CLAUDE.md), create .opencode/instructions/ and determine how to load OPENDOC.md. If opencode uses a different mechanism, document it and configure accordingly. This ensures the candidate profile and workflow rules are loaded as system context when the model starts.

6. Validation

  1. Task 2.8: Validate opencode.json

    Verify the JSON is syntactically valid (python3 -c "import json; json.load(open('opencode.json'))"). Verify the structure matches opencode's schema by cross-referencing with documentation and caroline's config. Check that all skill paths resolve to existing directories. Check that all tool names match opencode's tool vocabulary.
