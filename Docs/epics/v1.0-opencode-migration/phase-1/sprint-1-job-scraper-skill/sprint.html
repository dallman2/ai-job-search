Sprint 1: Job Scraper Skill

Phase: 1 Sprint: 1 Depends on: Phase 1 Sprint 0 (conventions)

Objective

Transform job-scraper/SKILL.md from a Step 0→1→2→3→4→5→6 procedural recipe into a goal-oriented skill (<70 lines). The scraper searches Danish job portals for new matching positions, deduplicates against seen jobs and the application tracker, performs a quick fit assessment, and presents results sorted by fit with handoff to the job-application-assistant skill.

Rationale & Context

The job-scraper is the discovery engine of the repo. It coordinates CLI job portal tools (jobindex, jobbank, jobnet, jobdanmark) with state management (seen_jobs.json) and the application tracker. The current SKILL.md (109 lines) has extensive procedural scaffolding — Step 0 Load State, Step 1 Search, Step 2 Fetch & Parse, Step 3 Quick Fit, Step 4 Deduplicate, Step 5 Present Results, Step 6 Update Tracker — plus an “Important Rules” section that lists constraints separately from the steps they govern.

In the goal-oriented model, the model should understand what the scraper achieves and what constraints bind it, then determine the execution path dynamically. The step-by-step order is already the logical order any model would pick; the step enumeration adds noise, not structure.

The search-queries.md file and the CLI tool invocations are tool references that stay intact; only the language directing the model changes.

Scope

In-Scope

  • Rewrite job-scraper/SKILL.md into goal-oriented format (target <70 lines)
  • Remove Step 0–6 enumeration; express workflow as goal + constraints
  • Merge “Important Rules” into the constraint body (rules that govern specific phases should be inline with those phases)
  • Preserve search-queries.md integration as a configurable strategy reference
  • Preserve deduplication logic, fit assessment framework, and output table format

Out-of-Scope

  • Modifying search-queries.md (it is configurable data, not procedural instruction)
  • Modifying the 4 CLI job portal tools in .agents/skills/
  • Changing the seen_jobs.json data format
  • Modifying job_search_tracker.csv structure
  • Adding new job portals or search strategies

Execution Plan

1. Rewrite Job Scraper SKILL.md

  1. Task 1.1.1: Rewrite SKILL.md as goal-oriented skill

    Transform the 109-line procedural SKILL.md into a goal-oriented format (<70 lines).

    Goal statement: “Your purpose is to search Danish job portals for new positions matching the candidate’s profile, deduplicate against previously seen jobs, and present ranked results.”

    Domain constraints to preserve (expressed as rules, not ordered steps):

    • State loading: Before searching, read job_scraper/seen_jobs.json (create empty if missing) and job_search_tracker.csv to extract already-applied companies and roles. Know the deduplication keys before you search.
    • Search strategy: Read search-queries.md for configured search categories. Run the top 3 priority categories by default; run all categories if the user asks for a broad search; prioritize a specific category if the user names a focus area. Use the job portal CLI tools (jobindex-search, jobbank-search, jobnet-search, jobdanmark-search) for structured search. Target the configured geographic area and postings from the last 14 days.
    • Pre-filter before fetching: Use titles and snippets to decide which results are worth fetching. Do not WebFetch every search result.
    • Fetching: For each promising result, use WebFetch to extract: job title, company, location, posting date (or “recent”), URL, key requirements (brief), and application deadline if listed. Skip any URL or company+title combo already in seen_jobs.json. Skip any company+role already in job_search_tracker.csv.
    • Deduplication: After fetching, add ALL jobs (new and skipped) to seen_jobs.json with title, company, URL, first_seen date, fit rating, and status. Only present jobs not already in the seen list or tracker.
    • Quick fit assessment: Rate each new job as High Match (core skills), Medium Match (adjacent experience), or Low Match (significant skill gaps). This is a rapid signal, not the full evaluation framework from 04-job-evaluation.md.
    • Output format: Present new jobs in a table sorted by fit (high first), with columns for Title, Company, Location, Deadline, and URL. For each high-match job, add 2–3 bullet points explaining the match, key requirements, and any red flags. After presenting, ask: “Want me to evaluate any of these in detail? Just give me the number(s).”
    • Handoff: If the user picks a number, invoke the job-application-assistant skill for full evaluation (fit assessment first, then CV + cover letter if approved).
    • Update tracker: If the user decides to apply to a job, add a row to job_search_tracker.csv.
    • Parallel searches: Use parallel tool calls to speed up the search phase across multiple portals.

    Remove: “Step 0” through “Step 6” headings. Remove the “How It Works” and “Invocation” sections (the goal statement replaces them). Remove the “Important Rules” section (constraints are now inline with the phases they govern). Never fabricate job postings — only present jobs found via actual search results.

2. Preserve search-queries.md Integration

  1. Task 1.1.2: Verify search-queries.md is referenced correctly

    Ensure the rewritten SKILL.md references search-queries.md as a configurable strategy source (not as a step to execute). The search-queries.md file itself requires no changes — it is a data file listing query categories, not procedural instruction. Verify the reference path resolves correctly relative to the skill directory.

3. Verification

  1. Task 1.1.3: Verify full scrape flow

    Verify the goal-oriented rewrite works end-to-end:

    • Skill loads via the skill tool (open with “find new jobs” or “scrape for jobs”)
    • State files are loaded (seen_jobs.json and job_search_tracker.csv)
    • CLI tools are invoked for search across configured portals
    • Results are deduplicated against seen jobs and tracker
    • Fit ratings are assigned (high/medium/low)
    • Results are presented in the correct table format sorted by fit
    • Handoff to job-application-assistant works when the user picks a job number
    • Parallel searches work (e.g., simultaneous jobindex + jobbank queries)
