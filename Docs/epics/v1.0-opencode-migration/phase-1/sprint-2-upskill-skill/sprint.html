Sprint 2: Upskill Skill

Phase: 1 Sprint: 2 Depends on: Phase 1 Sprint 0 (conventions)

Objective

Transform upskill/SKILL.md from a Step 1→2→3→4→5→6→7→8 procedural recipe (239 lines) into a goal-oriented skill (~100 lines). This is the largest transformation in Phase 1. The upskill skill analyzes skill gaps between the candidate’s profile and tracked or targeted jobs, then produces a prioritized heatmap, a learning plan with study resources, and a recommended study order.

Rationale & Context

The upskill skill is the most procedurally detailed skill in the repo. Its 239 lines describe an 8-step pipeline with precise formulas for skill frequency scoring, fit weighting, gap classification, and report assembly. This level of detail was necessary for a model following a recipe, but in a goal-oriented model, the methodology is domain knowledge the model applies within goal constraints — not an instruction manual it performs line by line.

The transformation must be careful: the two-pass methodology (Pass 1 hard-skill diff with frequency/weight scoring, Pass 2 LLM synthesis for domain/soft/tooling/credential gaps), the heatmap table format, the theme-grouped learning plan structure, and the study order dependency rules are all valuable domain IP. They survive as methodology constraints, not procedural steps.

The aggregate vs. targeted mode branch (from the old Step 1) becomes a constraint branch the model evaluates against the user’s input. The report composition rules (from the old Step 8) become an output format constraint.

Scope

In-Scope

  • Rewrite upskill/SKILL.md into goal-oriented format (target ~100 lines)
  • Remove Step 1–8 enumeration; express workflow as goal + methodology constraints
  • Preserve two-pass methodology: Pass 1 hard-skill diff (frequency/weight scoring) + Pass 2 LLM synthesis
  • Preserve aggregate vs. targeted mode branching as a constraint
  • Preserve heatmap table format, theme-grouped learning plan structure, and study order dependency rules
  • Merge “Important Rules” into the constraint body

Out-of-Scope

  • Modifying job_search_tracker.csv structure
  • Modifying 01-candidate-profile.md (read as input, not modified)
  • Changing the report file naming convention or save location
  • Adding new gap categories or scoring formulas
  • Modifying the output format for heatmaps, learning plans, or study orders

Execution Plan

1. Rewrite Upskill SKILL.md

  1. Task 1.2.1: Rewrite SKILL.md as goal-oriented skill

    Transform the 239-line procedural SKILL.md into a goal-oriented format (~100 lines). This is the largest content compression in Phase 1.

    Goal statement: “Your purpose is to analyze skill gaps between the candidate’s profile and tracked or targeted job postings, then produce a prioritized learning plan with study resources and a recommended study order.”

    Mode constraint (replaces old Step 1 branching logic):

    • If the user provides a URL or pasted job text, operate in targeted mode: analyze only that posting. Do not load the tracker.
    • If the user provides no URL, operate in aggregate mode: load job_search_tracker.csv and analyze all jobs.

    Methodology constraints (preserved from Steps 2–7, but expressed as rules, not ordered instructions):

    • Data loading (aggregate mode): Read job_search_tracker.csv (columns: date, company, sector, role, role_type, channel, status, contact_person, fit_rating, notes, cv_file, cover_letter_file, source). Read .opencode/skills/job-application-assistant/01-candidate-profile.md for current skills. Check upskill/ for the most recent aggregate report to enable the “Since Last Report” diff in the output.
    • Data loading (targeted mode): Use WebFetch to retrieve the posting. Extract job title, company, required/preferred skills, responsibilities, and domain context. Read the candidate profile for current skills. No tracker data.
    • Pass 1: Hard Skill Diff: Extract required and preferred technical skills from each job source. In aggregate mode, build a skill frequency map where each skill’s score = sum of ((100 - fit_rating) / 100) across all jobs — lower fit jobs contribute more weight to the gap score. In targeted mode, list required skills before preferred skills. Against the profile, be generous with matching: if the profile mentions a skill in any form (e.g., “Python” covers “Python scripting”), remove it from the gap list.
    • Pass 2: LLM Synthesis: Reason holistically about gaps the hard-skill diff misses. Consider domain knowledge, soft skills, tooling/process, and credential/certification gaps. Tag each as [domain], [soft], [tooling], or [credential]. Do not duplicate Pass 1 gaps.
    • Heatmap: Combine Pass 1 and Pass 2 into a prioritized table. Assign Critical (high-frequency/weight, or domain gaps across most jobs), High (moderate scores or consistent soft/tooling gaps), Medium (lower-frequency hard skills), and Low (one-off mentions). Always print the heatmap in the terminal as intermediate output before proceeding to the learning plan.
    • Learning plan: For every Critical and High gap (and Medium if fewer than 5 total gaps), produce a learning entry: 2–3 study resources found via WebFetch, a study direction tailored to the candidate’s existing background (be specific about what to skip), and a realistic time estimate. Group entries under theme headings (e.g., Cloud & Infrastructure, Domain Knowledge).
    • Study order: Number topics in recommended sequence. Dependencies first (“AWS networking” requires “AWS fundamentals”), Critical before High before Medium, quick wins early if fast (~5h), domain knowledge last. Include a total estimated time.
    • Report assembly: Assemble in order: header (mode + date), Since Last Report (aggregate only, omit if first report), Gap Heatmap, Learning Plan, Study Order. Save to upskill/report-YYYY-MM-DD.md (aggregate) or upskill/report-YYYY-MM-DD-<company>-<role>.md (targeted).

    Resource search rules (preserved from old “Important Rules”):

    • Never fabricate resources. Only cite resources found via actual WebFetch searches.
    • Include the current year in resource searches so results stay fresh.
    • Prefer hands-on courses over lecture-only content. Prefer official docs for tooling gaps. Prefer books for domain knowledge.
    • Omit Low-priority gaps from the learning plan (list them in the heatmap only).
    • Always save the report via Write. Do not skip even if the user seems satisfied with terminal output.

    Remove: “Step 1” through “Step 8” headings. Remove the “Overview” and “Invocation” sections (the goal statement replaces them). Remove the “Important Rules” section (rules are now inline). Remove the old detailed report template (the constraints describe the output format sufficiently).

2. Preserve Output Format Specifications

  1. Task 1.2.2: Verify output format constraints are complete

    Ensure the rewritten SKILL.md preserves all three output format specifications as constraints:

    • Heatmap table: Priority | Skill / Area | Type | Gap Source (with frequency/score attribution)
    • Theme-grouped learning entries: Heading, skill name with type tag, estimated hours, 2–3 resources with URLs and one-line rationale, tailored study direction
    • Study order table: Numbered sequence with Topic, Type, Estimated Time, and Dependency Note columns; total estimated time

    The old SKILL.md includes full example entries in code blocks. These example blocks are excessive as constraints (“the model will generate them by following the constraint, not by copying an example”). Shorten or remove example blocks; the format description itself is sufficient.

3. Verification

  1. Task 1.2.3: Verify both modes work end-to-end

    Verify the goal-oriented rewrite works in both modes:

    • Skill loads via the skill tool (open with “what should I learn” or “analyze skill gaps”)
    • Aggregate mode: loads tracker, builds frequency map with fit weighting, runs Pass 1 + Pass 2, prints heatmap, builds learning plan with resource search, writes study order, saves report
    • Targeted mode: WebFetch fetches the URL, extracts skills, runs Pass 1 + Pass 2, prints heatmap, builds learning plan, writes study order, saves report with slugified filename
    • “Since Last Report” diff works in aggregate mode (gaps closed, new gaps identified)
    • Report is always saved to upskill/ with correct filename convention
    • Pass 1 skill frequency scoring is correct (lower fit = higher weight)
