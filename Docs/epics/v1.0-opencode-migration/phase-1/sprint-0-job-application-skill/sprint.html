Sprint 0: Job Application Assistant + Subagent Definitions

Phase: 1 Sprint: 0 Depends on: Phase 0 (all sprints complete)

Objective

Transform job-application-assistant/SKILL.md from a Step 1→2→3→4 procedural recipe into a goal-oriented skill. In parallel, migrate the reviewer and research-expert subagent system prompts from standalone .opencode/agents/*.md files into opencode.json as persistent subagent definitions with full prompts (not stubs). Delete the standalone agent files afterward. This sprint establishes the goal-oriented writing conventions that Sprints 1–3 follow.

Rationale & Context

The job-application-assistant is the centerpiece of the repo — it coordinates the full apply workflow: evaluate fit, tailor CV, write cover letter, compile and verify PDFs, prepare interview materials. The current SKILL.md (62 lines post-Phase 0) retains the procedural structure even though Claude idiomatic language was stripped in Sprint 1. Its “Step 1: Research & Evaluate,” “Step 2: Tailor CV,” “Step 3: Write Cover Letter,” “Step 4: Interview Prep” headings must become goal statements.

The reviewer subagent is tightly coupled to this skill — it critiques drafts the drafter produces. Under Claude Code, the review prompt was a 60-line inline prompt constructed ad-hoc by the main model. opencode supports persistent subagents defined in opencode.json, which means the reviewer system prompt exists as configuration, not as generated text. The same applies to the research-expert subagent used for company and technology research.

Sprint 2 of Phase 0 created subagent stubs with placeholder prompts. This sprint fills in the full system prompts by migrating the content from .opencode/agents/reviewer.md (63 lines) and .opencode/agents/research-expert.md (49 lines) into opencode.json.

Execution Plan

1. Rewrite Job Application Assistant SKILL.md

  1. Task 1.0.1: Rewrite SKILL.md as goal-oriented skill

    Transform the 62-line procedural SKILL.md into a goal-oriented format (<80 lines). The opening sentence becomes the goal statement; everything else becomes domain constraints.

    Goal statement: “Your purpose is to assist the candidate with evaluating job postings and producing tailored, verified application materials.”

    Domain constraints to preserve (expressed as rules, not ordered steps):

    • Always evaluate fit first using the 5-dimension scoring framework in 04-job-evaluation.md before drafting. Present the evaluation table and verdict to the user; ask whether to proceed.
    • When drafting a CV, read the most relevant existing CV variant from cv/ as a starting point. Follow the tailoring rules in 05-cv-templates.md. Adjust profile statement, skills emphasis, experience bullet ordering, and section order to target the specific role.
    • When writing a cover letter, apply the style rules in 03-writing-style.md (no em-dashes, no cliches, active voice). Follow the template structure in 06-cover-letter-templates.md. Connect specific experience points to the role’s requirements.
    • After drafting, dispatch the reviewer subagent for critique. Read the reviewer’s Part A (structured edits) and Part B (narrative suggestions). Revise drafts incorporating feedback.
    • Compile and visually inspect both PDFs: CV with lualatex (exactly 2 pages, no orphaned \cventry titles), cover letter with xelatex (exactly 1 page, signature block must fit). Iterate until both pass.
    • Run the verification checklist from OPENDOC.md (factual accuracy, targeting, consistency, quality, compiled PDF) before presenting to the user. Report results as pass/fail.
    • When preparing interview materials, follow the framework in 07-interview-prep.md.
    • Never fabricate skills, experience, or achievements. All claims must match the candidate profile.
    • For AI tooling references in CVs/cover letters, use “opencode.”

    Goal variants (partial workflows expressed as constraint branches):

    • User wants evaluation only: stop after presenting the fit assessment and recommendation.
    • User wants CV only: skip cover letter and interview prep.
    • User wants cover letter only: skip CV and interview prep; use the most recent CV for context.
    • User wants interview prep only: skip document drafting; use the posting and profile directly.

    Remove: “Step 1,” “Step 2,” “Step 3,” “Step 4” headings. Remove the “Quick Commands” section (replaced by goal variants above). Remove the reference files table (the constraints reference files by name naturally).

2. Migrate Subagent Definitions into opencode.json

  1. Task 1.0.2: Register reviewer subagent with full system prompt

    If Sprint 2 created a reviewer stub, replace the stub prompt with the full system prompt from .opencode/agents/reviewer.md. If the stub was not created, add the reviewer subagent definition. The prompt content is already goal-oriented (“You are a hiring manager proxy reviewing a job application. Your purpose is to…”) and needs minimal editing — primarily removing Claude Code-isms if any remain (check for “Claude,” “Agent,” “AskUserQuestion”).

    Key elements to preserve:

    • Four-phase task structure: Research the Company, Read Reference Materials, Review the Drafts, Produce Feedback in Two Parts
    • Part A / Part B feedback format (structured edits as JSON + narrative suggestions)
    • Tool permissions: read-only (Read, WebFetch) with Edit/Write/Bash denied
    • Critical rules: ground suggestions in profile data, never fabricate, flag genuine gaps honestly, do not run verification checklist
  2. Task 1.0.3: Register research-expert subagent with full system prompt

    If Sprint 2 created a research-expert stub, replace the stub prompt. If not, add the definition. Migrate the full prompt from .opencode/agents/research-expert.md. The prompt is already goal-oriented and needs only a check for Claude-specific idioms.

    Key elements to preserve:

    • Research methodology: Inquiry Formulation, Research Execution, Information Synthesis, Quality Assurance
    • Research categories: Company Research, Technology Research, Learning Resources
    • Communication style directives: proactive, systematic, critical, efficient, transparent
    • Tool permissions: Read and WebFetch only (no Write/Bash)
  3. Task 1.0.4: Delete standalone agent files

    Once the full prompts are migrated into opencode.json and validated, delete .opencode/agents/reviewer.md and .opencode/agents/research-expert.md. The subagents now live exclusively in opencode.json as persistent, centrally-managed definitions. If the .opencode/agents/ directory becomes empty, remove it.

3. Verification

  1. Task 1.0.5: Verify skill loading and subagent dispatch

    Verify the goal-oriented rewrite works end-to-end:

    • Skill loads correctly via the skill tool (open with “evaluate this job posting” or “apply to this URL”)
    • Reviewer subagent dispatches via Task and returns structured Part A + Part B feedback
    • Research-expert subagent dispatches via Task and returns organized company research
    • Goal variants work: evaluation-only stops before drafting; CV-only skips cover letter; cover-letter-only skips CV; interview-prep-only skips documents
    • Full apply flow completes: URL → evaluation → draft CV + cover letter → reviewer critique → revise → compile PDFs → pass verification checklist
    • opencode.json remains syntactically valid after subagent definitions are added
