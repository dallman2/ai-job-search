Sprint 3: Profile Setup & Management Skill

Phase: 1 Sprint: 3 Depends on: Phase 1 Sprint 0 (conventions)

Objective

Create a new profile-setup skill that replaces the old /setup and /reset slash commands (deleted in Phase 0 Sprint 0). This skill guides the user through initial profile population and ongoing profile management — replacing placeholder tokens across OPENDOC.md and profile files with real data, validating profile completeness, and supporting incremental updates.

Rationale & Context

Under Claude Code, profile setup was a slash command (/setup) that walked the user through a form-filling workflow. Profile reset was a separate command (/reset) for re-running setup. Both were deleted when .claude/commands/ was removed in Sprint 0.8.

In the opencode model, profile setup is a skill the model loads when the user says they want to set up their profile. The skill does not dictate a rigid form-filling order; it declares what the profile needs to contain, which files hold which sections, and lets the model guide the user conversationally through population and validation.

This is the only Phase 1 skill that is created from scratch (the other three are rewrites of existing skills). However, it has clearly defined scope: the candidate profile sections are well-documented across OPENDOC.md and the 7 profile files in job-application-assistant/. The skill’s job is to know what goes where and guide the user through filling it in.

Scope

In-Scope

  • Create .opencode/skills/profile-setup/ directory with SKILL.md
  • Write a goal-oriented skill for profile population, validation, and updates (target <60 lines)
  • Define a profile file map documenting which sections live in which files
  • Define update workflows: add experience, update skills, change career goals, adjust deal-breakers, update behavioral traits
  • Define profile completeness validation rules
  • Register the new skill in opencode.json

Out-of-Scope

  • Modifying OPENDOC.md structure (the skill reads and writes it, but does not redesign its sections)
  • Modifying any of the 7 profile files in job-application-assistant/ (the skill reads and writes them; content structure stays)
  • Importing or parsing LinkedIn exports, CVs, or external profile data (future enhancement)
  • Integrating with the behavioral assessment framework (the skill can ask about traits but does not administer assessments)
  • Creating a web UI or form for profile editing

Execution Plan

1. Create Profile Setup SKILL.md

  1. Task 1.3.1: Create profile-setup SKILL.md

    Create the new directory .opencode/skills/profile-setup/ and write a goal-oriented SKILL.md (<60 lines).

    Goal statement: “Your purpose is to help the candidate populate, validate, and maintain their career profile across all profile files in the repo.”

    Sub-goals (expressed as constraint branches the model navigates based on user intent):

    • Initial population: The user is setting up their profile for the first time. Guide them through filling in every section, starting with the most important: identity and contact details, then education and experience, then skills, then career goals and preferences. Replace every [PLACEHOLDER_TOKEN] in OPENDOC.md and the profile files with the user’s actual information.
    • Validation: After any change, check profile completeness. Flag missing or placeholder-populated fields. Check that OPENDOC.md and 01-candidate-profile.md are consistent (no contradictory information). Check that 04-job-evaluation.md scoring dimensions reference real profile data, not placeholder tokens.
    • Update existing profile: The user wants to modify an existing section. Identify which file(s) contain that section (see profile file map). Ask for the new information, then update the relevant files.

    Profile file map (embedded as a constraint so the skill knows what lives where):

    • OPENDOC.md: Identity, education, professional experience, technical skills, certifications, publications, awards, behavioral profile (summary), what excites you, target sectors, deal-breakers.
    • .opencode/skills/job-application-assistant/01-candidate-profile.md: Extended identity (phone, email, LinkedIn, GitHub), education (detailed), professional experience (detailed), independent projects, technical skills (detailed), publications, awards, references.
    • .opencode/skills/job-application-assistant/02-behavioral-profile.md: Behavioral assessment results, strengths, growth areas, ideal environments.
    • .opencode/skills/job-application-assistant/04-job-evaluation.md: Skill match areas (strong/moderate/weak), experience match domains, career goals, motivation filter, life situation alignment.
    • .opencode/skills/job-application-assistant/03-writing-style.md: Writing style rules (mostly static; rarely modified during profile updates).
    • .opencode/skills/job-application-assistant/05-cv-templates.md and 06-cover-letter-templates.md: Template rules (static; not modified during profile setup).
    • .opencode/skills/job-application-assistant/07-interview-prep.md: STAR examples, tough questions (populated during setup, updated as user gains interview experience).

    Update workflows (constraints the model applies when the user has a specific update):

    • Add experience: User has a new role. Update the Professional Experience section in both OPENDOC.md and 01-candidate-profile.md. Add new experience domains to 04-job-evaluation.md if the role expands capability.
    • Update skills: User has learned a new skill or wants to adjust proficiency. Update the Technical Skills section in OPENDOC.md and 01-candidate-profile.md. Update skill match areas in 04-job-evaluation.md.
    • Change career goals: Update the Career Goals section in 04-job-evaluation.md and the What Excites You / Target Sectors sections in OPENDOC.md.
    • Update deal-breakers: Update the Deal-breakers section in OPENDOC.md.
    • Update behavioral traits: Update the Behavioral Profile section in OPENDOC.md and 02-behavioral-profile.md.
    • Add publication/award: Update the relevant section in both OPENDOC.md and 01-candidate-profile.md.

    Validation rules (constraints applied after any change):

    • No [PLACEHOLDER] tokens remain. If any are found, flag the incomplete section.
    • OPENDOC.md and 01-candidate-profile.md do not contradict each other (e.g., different job titles listed for the same role).
    • Career goals in 04-job-evaluation.md reference real skills from the profile, not placeholders.
    • Deal-breakers are specific and actionable (not generic like “bad culture”).
    • After validation, print a profile completeness summary: which sections are filled, which have placeholders, and any inconsistencies found.

2. Register the Skill and Validate

  1. Task 1.3.2: Register profile-setup in opencode.json

    Add .opencode/skills/profile-setup/ to the skills registration block in opencode.json. If the skill registration is done via opencode.json skill list, add the entry. If opencode auto-discovers skills from the .opencode/skills/ directory, verify the new skill is picked up.

    Ensure opencode.json remains syntactically valid after the addition.

  2. Task 1.3.3: Verify profile-setup skill end-to-end

    Verify the new skill works across all scenarios:

    • Skill loads via the skill tool (open with “set up my profile” or “update my profile”)
    • Initial population: All placeholder tokens across all files are identified and filled conversationally. OPENDOC.md and profile files are consistent.
    • Validation: Completeness check flags remaining placeholders. Consistency check catches contradictions between files.
    • Update existing profile: Add experience works (both OPENDOC.md and 01-candidate-profile.md updated). Update skills works (skills and 04-job-evaluation.md updated). Change career goals works. Update deal-breakers works. Update behavioral traits works.
    • Partial setup: User can set up identity and skills without filling in behavioral profile or interview prep.
    • Skill does not overwrite user-filled data when running validation (read-only inspection unless explicitly asked to change).
