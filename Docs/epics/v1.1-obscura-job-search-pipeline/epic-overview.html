Epic Overview: v1.1-obscura-job-search-pipeline

Epic Vision

Replace the manual job-posting copy/paste loop with an autonomous Obscura-powered search pipeline. The LLM can browse job boards directly via a headless browser MCP server, extract job descriptions from JS-rendered pages that WebFetch cannot reach, run those descriptions through the existing 5-dimension evaluation framework, and present scored results without the user needing to touch a browser.

The core directive: the LLM becomes the user's proxy on the web. It navigates Greenhouse, Ashby, Wellfound, and Y Combinator job boards, applies the search queries from search-queries.md, deduplicates against previously seen jobs, rapid-scores candidates, and hands off high-fit matches to the full job-application-assistant evaluation-and-drafting workflow. The user's role shifts from operator to decision maker.

Success means the user types "scrape jobs fast" in opencode and receives a ranked table of new job postings with fit scores, each backed by a full extracted description that the LLM read and evaluated from the live board.

Architecture

User finds job posting on LinkedIn/Greenhouse
     ↓
User copy/pastes URL into opencode chat
     ↓
LLM calls WebFetch (often fails on JS pages)
     ↓
User saves HTML file manually (postings/ dir)
     ↓
LLM reads saved file, evaluates, drafts

After (Obscura Autonomous Pipeline)

User: "scrape jobs fast"
     ↓
job-scraper skill executes search queries against boards
     ↓
Obscura MCP tools navigate + extract job descriptions
     ↓
Rapid fit scoring + deduplication
     ↓
Ranked table output: "6 high matches found"
     ↓
User: "evaluate #2"
     ↓
job-application-assistant runs full 5-dimension eval
     ↓
User: "draft CV and cover letter"

Component Architecture

opencode.json
  ├─ mcp.obscura (type: "remote", url: "http://127.0.0.1:8080/mcp")
  └─ subagents: reviewer, research-expert

Docker: h4ckf0r0day/obscura
  ├─ cmd: mcp --http --port 8080 --host 0.0.0.0 --stealth
  ├─ 30 MB memory, 85 ms page loads
  ├─ Stealth: anti-fingerprint + 3,520 tracker domains blocked
  └─ Binary: Rust, distroless/cc base, 57 MB compressed

job-scraper skill
  ├─ SKILL.md (rewritten for SF AI context)
  ├─ search-queries.md (5 priority tiers)
  ├─ seen_jobs.json (deduplication)
  └─ job_search_tracker.csv (application log)

Target Boards
  ├─ greenhouse.io (public job boards)
  ├─ jobs.ashbyhq.com (public job boards)
  ├─ wellfound.com (early-stage startups)
  ├─ ycombinator.com/jobs (YC companies)
  ├─ indeed.com (largest US job board, CDP-driven)
  └─ Google → LinkedIn public postings + direct career pages

Key Design Decisions

DecisionRationale
Docker, not binary in repo57 MB compressed image. distroless/cc base has no shell attack surface. docker run is a one-liner.
MCP HTTP mode (type: "remote")opencode connects via HTTP. No binary on PATH. No stdio subprocess management.
Stealth always onRandomized fingerprint per session. 3,520 tracker domains preemptively blocked. Prevents board bans before they happen.
LinkedIn via GoogleLinkedIn job search requires auth. Google indexes public postings. Career pages (OpenAI, Anthropic) caught by Google queries.
Indefinite seen_jobsJSON stores only URLs + timestamps (not descriptions). Trivially small. Easy to prune later.
"fast" (top 3) vs "deep" (all 5)User controls breadth/time tradeoff. Top 3 priority tiers cover agentic, dev-tooling, and frontier lab queries.

Conventions

  1. All skill files are goal-oriented: begin with "Your purpose is to..."
  2. MCP server registration follows the opencode remote MCP pattern: "type": "remote" with "url"
  3. Obscura MCP tools are used directly by the LLM; no wrapper scripts or CLI abstractions between the model and the browser
  4. Job descriptions are extracted as markdown via browser_snapshot and stored in seen_jobs.json for the evaluation phase
  5. Dedup keys: URL (primary) or normalized company+title (fallback for URL variants)
  6. All sprint plans follow the same HTML template as v1.0-opencode-migration
  7. The Docker container name is obscura; it runs in MCP HTTP mode, not the default CDP serve mode
  8. AI tooling references in generated CVs/cover letters continue to reference "opencode" by name (v1.0 convention, unchanged)

Epic Acceptance Criteria

  • docker ps shows obscura container running in MCP HTTP mode
  • opencode.json registers obscura as remote MCP server with enabled: true
  • LLM can navigate to a Greenhouse job posting and extract the full job description as markdown
  • LLM can navigate to an Ashby job posting and extract the full job description as markdown
  • LLM can search Wellfound and extract job listing results
  • LLM can search Y Combinator jobs and extract listing results
  • "scrape jobs fast" runs priority 1-3 queries across all configured boards
  • "scrape jobs deep" runs all 5 priority tiers
  • Output is a ranked, deduplicated table with fit scores (High/Medium/Low)
  • Picking a numbered result triggers full 5-dimension evaluation via job-application-assistant
  • Jobs already in seen_jobs.json or job_search_tracker.csv are not re-presented
  • A single board failure does not crash the batch; remaining boards continue
  • "scrape jobs new" returns only jobs posted since the last run timestamp
