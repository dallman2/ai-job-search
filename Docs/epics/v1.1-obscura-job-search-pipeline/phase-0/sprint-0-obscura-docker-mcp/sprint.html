Sprint 0: Obscura Docker & MCP Registration

Phase: 0 Sprint: 0 Depends on: —

Objective

Pull the Obscura Docker image, start the container in MCP HTTP mode with stealth enabled, register it as a remote MCP server in opencode.json, and smoke-test browser_navigate + browser_snapshot on all 4 target job boards. At the end of this sprint, the LLM can browse Greenhouse, Ashby, Wellfound, and Y Combinator job pages and extract clean markdown content from JS-rendered pages that WebFetch cannot reach.

Rationale & Context

WebFetch is a static HTTP fetcher. It cannot execute JavaScript. Greenhouse, Ashby, Wellfound, and YC Jobs all render job listings client-side via React or similar frameworks. The result is that WebFetch returns empty spinner divs or "You need to enable JavaScript to run this app" for every job board the candidate cares about. The user has been working around this by manually saving HTML files to postings/.

Obscura is a Rust headless browser engine that runs real JavaScript via V8, supports the Chrome DevTools Protocol for Puppeteer/Playwright compatibility, and exposes an MCP server with browser_navigate, browser_snapshot, browser_evaluate, and other tools. It uses 30 MB of memory (vs 200+ MB for headless Chrome), loads pages in 85 ms (vs ~500 ms), and has built-in stealth mode that blocks 3,520 tracker domains and randomizes browser fingerprints per session.

The Docker image is h4ckf0r0day/obscura on Docker Hub. It is multi-stage, builds from rust:1-slim-bookworm, and runs on distroless/cc-debian12 with no shell and no package manager. The compressed image is 57 MB. The default ENTRYPOINT is /obscura and the default CMD is ["serve", "--port", "9222", "--host", "0.0.0.0"]. For MCP mode, we override CMD to run mcp --http --port 8080 --host 0.0.0.0 --stealth.

opencode supports remote MCP servers via "type": "remote" with a "url" pointing to the MCP endpoint. The Obscura MCP HTTP endpoint is at /mcp (SSE transport).

Execution Plan

1. Pull and Start Obscura

  1. Task 0.1: Pull the Obscura Docker image

    docker pull h4ckf0r0day/obscura. Verify with docker images | grep obscura. Expected: ~57 MB compressed image.

  2. Task 0.2: Start container in MCP HTTP mode with stealth

    docker run -d --name obscura -p 127.0.0.1:8080:8080 h4ckf0r0day/obscura mcp --http --port 8080 --host 0.0.0.0 --stealth

    This overrides the default CMD (serve) with mcp. The --host 0.0.0.0 flag binds to all interfaces inside the container so the port mapping works. --stealth enables anti-fingerprinting and tracker blocking.

2. Verify Container Health

  1. Task 0.3: Verify container is running

    docker ps --filter name=obscura. Confirm status is "Up" and port mapping shows 127.0.0.1:8080->8080/tcp.

  2. Task 0.4: Verify MCP endpoint responds

    docker logs obscura should show the server started successfully. Test the SSE endpoint: curl -s http://127.0.0.1:8080/mcp/sse should return an SSE event stream.

    Fallback if --host flag is unsupported by mcp subcommand: remove and recreate the container with --network host instead of port mapping: docker rm -f obscura && docker run -d --name obscura --network host h4ckf0r0day/obscura mcp --http --port 8080 --stealth.

3. Register MCP Server in opencode

  1. Task 0.5: Add obscura MCP server to opencode.json

    Add an "mcp" block to opencode.json with the obscura server configured as a remote HTTP MCP:

    "mcp": {
  "obscura": {
    "type": "remote",
    "url": "http://127.0.0.1:8080/mcp",
    "enabled": true,
    "timeout": 30000
  }
}

    The timeout of 30000 ms accounts for page loads that may exceed the default 5-second limit. Job board pages with heavy JS can take 10-15 seconds to render.

4. Smoke Test: Greenhouse

  1. Task 0.6: Navigate to a Greenhouse job posting and extract content

    Use the existing Thinking Machines Lab DevProd posting as a test case: https://job-boards.greenhouse.io/thinkingmachines/jobs/5111543008. Call browser_navigate with the URL, then browser_snapshot to extract the page content. Verify the output includes the job title ("Software Engineer, Developer Productivity, AI Tools"), location ("San Francisco"), and body content.

    Expected: clean markdown output containing the full job description. No "You need to enable JavaScript" messages. No empty divs.

5. Smoke Test: Ashby

  1. Task 0.7: Navigate to an Ashby job posting and extract content

    Use the Wispr Flow posting: https://jobs.ashbyhq.com/wispr-flow/8a9f60cd-ab73-42d6-9450-94dfbe80886e. Call browser_navigate then browser_snapshot. Verify the output includes the job title ("Senior Software Engineer"), company ("Wispr Flow"), and body content.

6. Smoke Test: Wellfound

  1. Task 0.8: Navigate to a Wellfound search results page

    Navigate to a Wellfound AI engineering search: https://wellfound.com/jobs?keywords=AI+engineer&location=san-francisco. Call browser_navigate with waitUntil: "networkidle0" (Wellfound loads listings dynamically), then browser_snapshot. Verify job listing cards appear in the output.

7. Smoke Test: Y Combinator Jobs

  1. Task 0.9: Navigate to a YC jobs search page

    Navigate to https://www.ycombinator.com/jobs?tags=ai. Call browser_navigate then browser_snapshot. Verify job listing cards appear. Confirm pagination is visible (YC uses standard pagination, no infinite scroll).

8. Verify Stealth Mode

  1. Task 0.10: Confirm no blocks or captchas on any board

    For each of the 4 boards above, confirm that the page rendered normally without: Cloudflare "checking your browser" interstitial, reCAPTCHA challenges, empty or truncated content, HTTP 403 responses. Stealth mode should handle all of these preemptively.

Deviation: HTTP mode replaced with stdio mode

The obscura mcp --http command binds to 127.0.0.1 inside the container but lacks a --host flag to bind to 0.0.0.0. Docker port forwarding (-p) cannot reach loopback-bound ports. The serve subcommand supports --host 0.0.0.0 but mcp does not. The workaround is stdio mode: opencode spawns docker run -i --rm ... mcp --stealth and communicates over stdin/stdout, which works correctly across the container boundary. This is functionally equivalent — the same MCP server, same tools, just a different transport.
