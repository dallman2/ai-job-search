Sprint 2: Fit Scoring & Evaluation Handoff

Phase: 0 Sprint: 2 Depends on: Sprint 1

Objective

Wire the scraper's rapid-scored results into the full job-application-assistant 5-dimension evaluation pipeline. Define the ranked output table format. Implement the numbered-selection handoff: user picks a job number, the LLM loads the extracted job description from seen_jobs.json, invokes the application assistant skill with the full evaluation framework, and presents a scored verdict. Update state on evaluation. At the end of this sprint, the user can go from "scrape jobs fast" to a full fit analysis by typing a single number.

Rationale & Context

Sprint 1 produces rapid-scored, deduplicated job listings. Rapid scoring is a keyword-based pre-filter: it catches obvious mismatches before the LLM spends time on detail pages, but it does not replace the full evaluation. The 5-dimension framework in 04-job-evaluation.md (Technical Skills, Experience, Behavioral Fit, Location, Career Alignment) requires reading the full job description and reasoning against the complete candidate profile — a task that needs the application assistant's context (profile data, behavioral profile, writing style rules).

The handoff from scraper to evaluator must be seamless. The scraper extracts and stores job descriptions in seen_jobs.json. When the user picks a number, the LLM loads the matching entry from the JSON, invokes the job-application-assistant skill with the description as context, and runs the full evaluation. The result is presented in the standard 5-dimension table format from 04-job-evaluation.md.

State tracking is critical: after evaluation, the job's status in seen_jobs.json updates from new to evaluated. If the user decides to apply, a row is appended to job_search_tracker.csv. If the user generates a CV and cover letter (via the application assistant's drafting workflow), those files exist at their standard paths (cv/main_<company>.md, cover_letters/cover_<company>_<role>.md).

Scope

In-Scope

  • Define the ranked output table format with numbered entries, fit badges, and key match signals
  • Implement the numbered-selection handoff from scraper results to full evaluation
  • Load the full job description from seen_jobs.json for the selected entry
  • Invoke job-application-assistant skill with the job description for full 5-dimension evaluation
  • Present evaluation as: scoring table, verdict, key strengths, gaps to address, recommendation
  • After evaluation, prompt: "Want to generate a tailored CV and cover letter?"
  • Update seen_jobs.json status to evaluated after eval
  • If user confirms application: append row to job_search_tracker.csv
  • Link generated documents in the output (file paths to CV and cover letter)

Out-of-Scope

  • Modifying the job-application-assistant evaluation framework (unchanged from v1.0)
  • Modifying the CV or cover letter drafting workflow (unchanged)
  • Batch evaluation of multiple jobs (one at a time via numbered selection)
  • Auto-applying or form-filling
  • Salary benchmark lookup (tool is optional, unchanged)

Execution Plan

1. Define Ranked Output Table

  1. Task 2.1: Define output table schema in SKILL.md

    Add the following output format specification to the skill's Output section:

    ## Job Search Results -- [date]

| # | Fit | Title | Company | Location | Key Match | 
|---|-----|-------|---------|----------|------------|
| 1 | HIGH | Senior SWE, DevProd | Thinking Machines | SF | MCP, K8s, AI tools |
| 2 | HIGH | Senior SWE | Wispr Flow | SF | Voice AI, TS/React |
| 3 | MED | Platform Engineer | ExampleCo | Remote | K8s, TypeScript |
...

6 high matches, 4 medium matches, 12 low matches skipped.

Want me to evaluate any of these in detail? Just give me the number(s).

2. Implement Evaluation Handoff

  1. Task 2.2: Add evaluation handoff logic to SKILL.md

    When the user provides a number:

    1. Look up the entry in seen_jobs.json by the index from the output table.
    2. Load the full job description stored during the fetch phase.
    3. Invoke the job-application-assistant skill with the job description and the instruction: "Evaluate this job posting against the candidate profile using the 5-dimension evaluation framework in 04-job-evaluation.md. Present the evaluation table, verdict, key strengths, gaps, and recommendation."
    4. After evaluation results are returned, update seen_jobs.json: set status to evaluated for that entry.
    5. Prompt: "This is a [Strong/Good/Moderate/Weak/Poor] Fit. Want me to generate a tailored CV and cover letter?"
  2. Task 2.3: Add application tracking logic to SKILL.md

    If the user says yes to drafting, the job-application-assistant skill handles CV and cover letter generation (its existing workflow, unchanged). After documents are generated, the scraper updates seen_jobs.json status to applied and appends a row to job_search_tracker.csv.

    CSV row format: company,role,date_applied,status,notes. The date_applied is the current date. status is applied. notes includes links to the generated CV and cover letter file paths.

3. Update State Management

  1. Task 2.4: Document state transitions in SKILL.md

    Define the status lifecycle for jobs in seen_jobs.json:

    new        → job found in current scrape, not yet evaluated
evaluated  → full 5-dimension evaluation completed
skipped    → pre-filtered out (low match, duplicate, expired)
applied    → CV + cover letter generated and (presumably) submitted

Verification & Acceptance Criteria

  • After a scrape run, output is a numbered table with columns: Fit, Title, Company, Location, Key Match
  • User types "evaluate #2" and the LLM loads job #2's description from seen_jobs.json
  • Full evaluation output matches the format in 04-job-evaluation.md: scoring table, verdict, strengths, gaps, recommendation
  • After evaluation, seen_jobs.json shows status: evaluated for that entry
  • After evaluation, user is prompted: "Want me to generate a tailored CV and cover letter?"
  • If user confirms generation, job-application-assistant produces CV and cover letter at standard paths
  • After generation, seen_jobs.json status updates to applied and job_search_tracker.csv gets a new row
  • Evaluated or applied jobs do not appear in subsequent scrape runs
