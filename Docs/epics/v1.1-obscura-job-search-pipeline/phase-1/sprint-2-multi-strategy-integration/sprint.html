Sprint 2: Multi-Strategy Integration & Full Smoke Test

Phase: 1 Sprint: 2 Depends on: Sprint 1

Objective

Wire the board-list and cookie-auth search strategies into a single unified pipeline with clean flag-based control. Add error handling for mixed-strategy failures. Update output formatting to report which strategies contributed results. Run a full end-to-end smoke test proving the pipeline returns jobs from 5+ companies across 3+ board platforms. Update the epic overview and acceptance criteria to reflect multi-strategy coverage. At the end of this sprint, Phase 1 is production-grade.

Rationale & Context

Sprint 0 delivers board-list search (30-50 companies, no auth). Sprint 1 delivers cookie-auth search (LinkedIn, Wellfound). But they're separate paths. The user doesn't want to run three separate commands. "scrape jobs fast" should run the most effective available strategy combination by default and present unified results.

The default fast path: board-list runs first (fastest, most reliable, covers 80% of target companies). If cookie files are present, LinkedIn and Wellfound searches supplement. All results flow through the same dedup and scoring pipeline. The user sees one table.

The smoke test is critical because Phase 0's smoke test was the canary that revealed the coverage gap. Phase 1's smoke test must prove we fixed it.

Execution Plan

0. Build CDP Search Client for LinkedIn and Wellfound

  1. Task 2.0a: Create CDP search client

    Build a Python script that drives the user's real Chrome instance via CDP to execute LinkedIn and Wellfound job searches. The real Chrome is already signed in — no cookie files, no injection, no headless browser bot detection.

    The script reuses CDP WebSocket infrastructure from export_chrome_cdp.py and adds page navigation, load-event waiting, and DOM extraction. It exposes a CLI:

    • python3 cdp_search.py linkedin "keywords" --count N --experience 4,5,6 → JSON array of {title, company, location, url}
    • python3 cdp_search.py wellfound "keywords" --count N → JSON array of {title, company, location, salary, url}
    • python3 cdp_search.py status → {chrome: bool, tabs: int}

    Accepts that Obscura's bundled Chromium cannot execute LinkedIn/Wellfound JS (bot detection). The CDP approach works because it's the user's actual browser instance with full JS execution and no fingerprinting anomalies.

  2. Task 2.0b: Wire CDP client into SKILL.md

    Replace all cookie-injection-based LinkedIn/Wellfound search instructions with CDP-driven search. Remove cookie-file dependency for search flow (Sprint 1 cookie export remains valid for diagnostics). Update error resilience: Chrome CDP unreachable → skip LinkedIn/Wellfound, continue with board-list.

1. Unify Strategy Execution

  1. Task 2.1: Define unified strategy execution order in SKILL.md

    Update the Search section to describe the unified execution flow:

    1. Board-list search (always runs): Visit each company's board URL via webfetch/Obscura. Extract listing URLs. Pre-filter by location and level. Collect all promising listing URLs.
    2. LinkedIn search (if Chrome CDP is reachable and default mode or --linkedin flag): Run cdp_search.py linkedin "keywords" via bash. Parse JSON output for listing URLs.
    3. Wellfound search (if Chrome CDP is reachable and default mode or --wellfound flag): Run cdp_search.py wellfound "keywords" via bash. Parse JSON output for listing URLs.
    4. Unified dedup + fetch: All collected listing URLs flow into the Fetch & Deduplicate phase. Dedup across all strategies.
  2. Task 2.2: Update flag detection logic

    Update run mode triggers in the State section:

    • "fast" (default): board-list (15-20 prioritized companies) + LinkedIn + Wellfound (if cookies)
    • "deep": full board-list (all companies) + LinkedIn + Wellfound (if cookies)
    • "board-list": board-list only, skip all cookie-auth strategies
    • "--linkedin": include LinkedIn search (requires cookies)
    • "--wellfound": include Wellfound search (requires cookies)
    • "new": diff against last_run, compatible with all strategies

2. Error Handling for Mixed Strategies

  1. Task 2.3: Add mixed-strategy error handling to SKILL.md

    Update the Error Resilience section to handle mixed-strategy failures:

    • If a cookie file exists but injection fails or cookies are expired: skip that strategy, continue with others, report in Issues.
    • If a board-list company's board URL returns 5xx: skip that company, continue with remaining companies.
    • If ALL strategies produce zero results: report "No jobs found across any strategy. Board-list returned 0, [LinkedIn/Wellfound skipped or returned 0]."
    • Track per-strategy failure counts in run state for reporting.

3. Output Format Updates

  1. Task 2.4: Update output format for multi-strategy results

    Update the Output section:

    • Summary line: "Found [total] jobs from [N] companies across [strategy list]. [high] high matches, [med] medium matches. [skipped] low matches skipped."
    • Example: "Found 47 jobs from 8 companies (board-list: Anthropic, OpenAI, LangChain, ElevenLabs, Modal; LinkedIn: 3 additional). 11 high matches, 9 medium matches. 27 skipped."
    • Issues section reports per-strategy failures: "LinkedIn cookies expired — re-export from browser. Wellfound returned no results."
    • If strategies were skipped due to missing cookies: "LinkedIn skipped (no cookies). Wellfound skipped (no cookies). Run 'scrape jobs fast --linkedin' after exporting cookies."
  2. Task 2.5: Update run_history tracking for multi-strategy runs

    Extend the run_history entry schema to track per-strategy results:

    {
  "date": "2026-06-08T14:30:00Z",
  "mode": "fast",
  "strategies": ["board-list", "linkedin"],
  "companies_checked": 18,
  "jobs_found": 47,
  "jobs_new": 20,
  "strategies_failed": ["wellfound"]
}

4. Full Smoke Test

  1. Task 2.6: Run full end-to-end smoke test

    Execute "scrape jobs fast" with the following acceptance bar:

    • Board-list search visits 15-20 company boards
    • At least 3 distinct companies produce results
    • Results come from at least 2 different ATS platforms (Greenhouse + Ashby/Lever)
    • If Chrome CDP is reachable, LinkedIn and/or Wellfound produce supplementary results (at least 3 distinct listings each)
    • No single board failure crashes the pipeline
    • Output table contains 5+ non-Anthropic companies
    • Summary line reports strategy breakdown
    • Issues section reports any failures (expected: Wellfound may still have issues)

5. Update Epic Docs

  1. Task 2.7: Update epic-overview.html with Phase 1 completion

    Update the Phase Structure table: set Phase 1 status to "completed". Update epic acceptance criteria to include multi-strategy coverage: "scrape jobs fast returns jobs from 5+ distinct companies across 3+ board platforms."
