Sprint 0: Direct Board List

Phase: 1 Sprint: 0 Depends on: Phase 0

Objective

Build a reliable, no-auth-required search path that covers 80% of target companies by replacing Google discovery with a curated list of company career pages organized by ATS platform. Create board-list.md with 30-50 target companies and their board URLs. Update the job-scraper SKILL.md to load and iterate the board list during the search phase. At the end of this sprint, "scrape jobs fast" returns jobs from 5+ distinct companies across multiple board platforms without touching Google at all.

Rationale & Context

The Phase 0 smoke test revealed that 4 of 5 search strategies fail: Google site: queries hit CAPTCHA blocks, Wellfound requires login, YC Jobs SF filter returns globally-scattered results, and LinkedIn is unreachable without authentication. Only direct Greenhouse/Ashby/Lever board navigation worked reliably. This is actually good news: the vast majority of target companies (frontier AI labs, AI-native infrastructure startups, devtools companies) host jobs on Greenhouse, Ashby, or Lever — all of which expose public job boards with no authentication required.

The current search strategy uses Google site: queries to discover which companies are hiring, then navigates to individual postings. This is the wrong order. We already know which companies we want to work for. The board list inverts the approach: start with a known-good list of company career pages, navigate directly to each, extract current listings, and score them. No discovery step needed.

This is the highest-impact, lowest-risk change in Phase 1. No new infrastructure. No cookies to manage. Just a well-researched list and a small skill update.

Scope

In-Scope

  • Research and compile 30-50 target company career pages organized by ATS platform
  • Coverage targets: frontier AI labs, AI-native infrastructure/devtools startups, agentic/MCP companies, voice/multimodal AI companies
  • Each entry: company name, board URL, board type (Greenhouse/Ashby/Lever/custom), role filter tags, notes
  • Create .opencode/skills/job-scraper/board-list.md with the curated list
  • Update SKILL.md State section: load board-list.md alongside existing config files
  • Update SKILL.md Search section: add board-list iteration as a search strategy; navigate to each board URL, extract listing titles and URLs, collect across all boards before moving to deduplication
  • Update run mode triggers: "board-list" flag runs board-list only (fastest, most reliable path); "fast" defaults to board-list when available
  • Test against live boards: verify listing extraction works on Greenhouse, Ashby, and Lever boards

Out-of-Scope

  • Cookie injection or authenticated board access (Sprint 1)
  • Google site: query fixes (superseded by board list)
  • LinkedIn or Wellfound search (Sprint 1)
  • Multi-strategy orchestration (Sprint 2)
  • Modifying search-queries.md (still used as fallback; Google queries remain for future auth-based recovery)
  • Web scraping laws or rate-limit concerns (public job boards are intended for browsing)

3. Update SKILL.md

  1. Task 0.5: Add board-list state loading to SKILL.md

    Update the State section: add board-list.md to the files loaded during initialization. The board list provides direct URLs to company career pages, bypassing Google discovery entirely.

  2. Task 0.6: Add board-list iteration to Search phase

    Add board-list search strategy to the Search section:

    Board-list search (primary, no-auth)
    For each company in board-list.md, navigate to the board URL via browser_navigate. Extract listing titles and URLs from the job board page. Collect all listing URLs before moving to the Fetch phase. Parallel navigation where the board supports it. Pre-filter by location (SF/Remote) and level (Senior+) from listing snippets.

    Board-list search runs first — it's the fastest and most reliable path. Other search strategies (search-queries, cookie-auth) supplement it.

  3. Task 0.7: Update run mode triggers for board-list

    Add board-list mode detection: if the user says "board-list" or the default "fast" mode is triggered and board-list.md exists, run board-list search as the primary strategy. Board-list search is compatible with fast/deep/new modes. "fast" with board-list runs the first 15-20 companies (prioritized by category). "deep" runs the entire list.

4. Smoke Test

  1. Task 0.8: Test board-list extraction on 5+ companies

    Navigate to the board URLs for Anthropic, OpenAI, LangChain, ElevenLabs, and one additional company. Verify that listing titles and URLs can be extracted from each board page. Verify that detail pages load correctly when navigated to from the listing URLs.

  2. Task 0.9: Confirm diversity of results

    Run a fast board-list scrape. Verify that results come from at least 3 distinct companies across at least 2 different ATS platforms (Greenhouse + Ashby + Lever). This confirms the board list solves the "only Anthropic" problem.
