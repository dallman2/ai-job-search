Sprint 1: Cookie Injection & Authenticated Boards

Phase: 1 Sprint: 1 Depends on: Sprint 0

Objective

Extend Obscura with the candidate's real browser session cookies so LinkedIn and Wellfound — the two remaining gated boards — become accessible to the pipeline. Document the cookie export process from Chrome/Firefox. Create a gitignored cookie storage directory. Update the job-scraper SKILL.md with cookie injection workflows, LinkedIn public job search, Wellfound browsing, and cookie expiry handling. At the end of this sprint, "scrape jobs fast --linkedin" returns public job postings from LinkedIn and "scrape jobs fast --wellfound" returns listings from Wellfound.

Rationale & Context

Sprint 0's board list covers 80% of target companies via Greenhouse/Ashby/Lever — but it has a structural blind spot. Some high-signal roles are only posted on LinkedIn. Some valuable startups only list on Wellfound. And LinkedIn's public job index, while accessible without login for individual postings, requires authentication for search.

Obscura provides browser_set_cookie (set a cookie by name, value, domain) and browser_get_cookies (export all cookies from the jar). This means we don't need to run a full authenticated browser session inside Obscura. Instead, the candidate exports their session cookies once from their real browser (where they're already logged into LinkedIn, Wellfound, etc.), drops the file into a gitignored directory, and the skill injects those cookies before navigating to gated domains.

This approach is superior to running a persistent Chrome session because: (1) no browser process to manage, (2) cookies are a static file — no session refresh mid-scrape, (3) the candidate controls exactly which cookies are shared (only session tokens, never passwords), (4) cookies can be refreshed by re-exporting from the real browser when they expire (typically weeks or months for LinkedIn).

The key risk is cookie expiry. LinkedIn sessions last ~2 weeks. Wellfound sessions vary. The skill must detect expiry (redirect to login page) and report clearly rather than silently failing with empty results.

  • Document the CDP cookie export workflow: start Chrome with --remote-debugging-port=9222, navigate to the target site, run the script
  • Provide a JavaScript console fallback snippet for non-httpOnly cookies (quick but incomplete — cannot extract li_at for LinkedIn)
  • Create .opencode/skills/job-scraper/cookies/ directory with .gitignore (all cookie files are never committed)
  • Define cookie file format: JSON array of {name, value, domain, path, secure, httpOnly} objects
  • Provide a JavaScript console fallback snippet for non-httpOnly cookies (quick but incomplete — cannot extract li_at for LinkedIn)
  • Update SKILL.md State section: load cookie files if they exist; skip gracefully if missing
  • Update SKILL.md Search section: before navigating to a gated domain, inject cookies via browser_set_cookie; navigate to LinkedIn search URL with query parameters; navigate to Wellfound search URL; extract listing URLs from result pages
  • Add cookie expiry detection: after navigation, check if URL redirected to linkedin.com/login or wellfound.com/login; if so, report "cookies expired, re-export from browser" and skip the board
  • Add LinkedIn search queries to search-queries.md Priority 4 section: authenticated LinkedIn search URLs with SF filter and Senior+ level
  • Update run mode triggers: --linkedin and --wellfound flags for targeted authenticated searches
  • Test LinkedIn search and Wellfound search with live cookies

Out-of-Scope

  • Automated cookie refresh or session management (user re-exports manually)
  • Password-based login inside Obscura (security risk; cookies only)
  • LinkedIn Easy Apply or form-filling (auto-apply is deferred)
  • Wellfound authenticated profile browsing or messaging
  • Cookie encryption at rest (local machine only; gitignored)
  • Multi-account cookie profiles

Execution Plan

1. Create Cookie Infrastructure

  1. Task 1.1: Create cookies directory and .gitignore

    Create .opencode/skills/job-scraper/cookies/ with a .gitignore that ignores all *.json files. Create a README.md with cookie export instructions for Chrome and Firefox.

  2. Task 1.2: Write the CDP cookie extraction script

    Write a Python script that exports cookies from a running Chrome instance via the Chrome DevTools Protocol. The script must:

    • Connect to Chrome's debug endpoint at http://localhost:9222/json to discover open tabs
    • Locate the tab matching the target domain (e.g., linkedin.com) and retrieve its WebSocket debugger URL
    • Send the Network.getCookies CDP command over WebSocket to retrieve all cookies including httpOnly (which document.cookie cannot access)
    • Format the response as a JSON array of {name, value, domain, path, secure, httpOnly} objects
    • Use only Python standard library — no pip dependencies, no browser extensions, no Keychain access

    Design decision: The initial plan specified EditThisCookie and manual DevTools export. This was revised to a CDP script because browser extensions that read all cookies are a security vulnerability. CDP accesses Chrome's own debugging protocol on localhost, which is the intended mechanism for tooling to interact with the browser. The script owns the extraction end-to-end — no third-party code touches the cookies.

    See also: Cookie Export via CDP Recipe for the full implementation rationale and usage guide.

  3. Task 1.3: Document CDP export workflow in README.md

    Document the complete CDP cookie export workflow in cookies/README.md:

    • How to start Chrome with --remote-debugging-port=9222
    • How to run export_chrome_cdp.py for LinkedIn and Wellfound
    • Cookie file format specification
    • Required cookies per site (LinkedIn: li_at + JSESSIONID)
    • Cookie expiry and refresh process
    • JavaScript console snippet as a quick fallback for non-httpOnly cookies
    • Security notes: files are gitignored, no passwords, localhost only

2. Update SKILL.md for Cookie-Auth Search

  1. Task 1.4: Add cookie state loading to SKILL.md

    Update the State section: after loading the standard config files, check for cookie files in cookies/. If cookies/linkedin.json exists, load it for LinkedIn search. If cookies/wellfound.json exists, load it for Wellfound search. If a cookie file is missing, the corresponding board is skipped (no error).

  2. Task 1.5: Add cookie injection workflow to Search section

    Add cookie-based search strategy to the Search section:

    LinkedIn search (cookie-auth required)
    Load cookies from cookies/linkedin.json. Inject each cookie via browser_set_cookie for domain .linkedin.com. Navigate to LinkedIn job search: https://www.linkedin.com/jobs/search/?keywords=[query]&location=San+Francisco+Bay+Area&f_E=4,5,6 (Senior+ level filter). Extract listing URLs and titles from the search result cards. Navigate to each detail page for full description.
    Wellfound search (cookie-auth required)
    Load cookies from cookies/wellfound.json. Inject each cookie via browser_set_cookie for domain .wellfound.com. Navigate to Wellfound search: https://wellfound.com/jobs?search=[query]&location=san-francisco. Use waitUntil: "networkidle0" for dynamic listing loads. Extract listing URLs and titles.

    Cookie-based searches run after the board-list search. They are supplementary — if cookies are missing or expired, the pipeline continues with board-list results only.

  3. Task 1.6: Add cookie expiry detection to SKILL.md

    After navigating to a gated domain, check the resulting URL: if it redirected to a login page (linkedin.com/login, wellfound.com/login, or a /auth path), report "LinkedIn/Wellfound cookies have expired. Re-export from your browser and save to cookies/." Skip the board for this run. Do not crash the pipeline. Add the failure to the Issues section of the output.

3. Update Search Queries

  1. Task 1.7: Add authenticated LinkedIn search URLs to search-queries.md

    Update Priority 4 (LinkedIn via Google) to include direct LinkedIn search URLs for use with cookie-auth:

    ### Priority 4: LinkedIn (Authenticated Search)

When cookies/linkedin.json is available, use direct LinkedIn search:
https://www.linkedin.com/jobs/search/?keywords="senior" OR "staff" OR "lead" engineer agentic MCP&location=San+Francisco+Bay+Area&f_E=4,5,6
https://www.linkedin.com/jobs/search/?keywords="platform engineer" AI agent San Francisco&location=San+Francisco+Bay+Area&f_E=4,5,6

f_E=4,5,6 filters to Senior, Director, and Executive levels only.

    Keep the existing Google → LinkedIn fallback queries for when cookies are not available.

4. Test with Live Cookies

  1. Task 1.8: Test CDP script with live cookies

    Start Chrome with --remote-debugging-port=9222, navigate to linkedin.com, sign in. Run python3 cookies/export_chrome_cdp.py linkedin.com. Verify the output is a valid JSON array containing cookies with all required fields (name, value, domain, path, secure, httpOnly). Confirm the critical li_at cookie (httpOnly) is present — this is the test that CDP passes and the console snippet fails.

  2. Task 1.9: Test Wellfound authenticated browsing

    With cookies/wellfound.json populated, navigate to a Wellfound search URL. Verify that job listing cards appear (not a login wall). Extract listing URLs and navigate to a detail page.

  3. Task 1.10: Test cookie expiry detection

    Intentionally use expired or invalid cookies. Verify that the skill detects the login redirect, reports the expiry, and continues with remaining boards without crashing.
