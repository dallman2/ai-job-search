Sprint 3: Indeed Integration

Phase: 1 Sprint: 3 Depends on: Sprint 2

Objective

Add Indeed.com as a supplementary CDP-driven search source alongside LinkedIn and Wellfound, expanding Phase 1 search coverage to the largest public job board in the US. Indeed is the highest-volume job board and captures roles from companies that do not use Greenhouse/Ashby/Lever (the board list) and do not post on LinkedIn or Wellfound. Adding it fills the last major coverage gap in the Phase 1 multi-strategy architecture.

Rationale & Context

Sprint 2 unified board-list, LinkedIn, and Wellfound into a single pipeline. That pipeline now covers ~90% of the target search surface — but there's a structural blind spot: many companies post exclusively on Indeed. Indeed is the highest-volume job board in the United States by a wide margin, and no other strategy in the Phase 1 portfolio reaches it.

Fortunately, Indeed can reuse the same CDP infrastructure that Sprint 2 built for LinkedIn and Wellfound. Indeed's job search results page is JS-rendered and requires a real browser for extraction — the exact use case cdp_search.py was built for. No new infrastructure is needed. The work is additive: one new subcommand, one new extraction scriptlet, and wiring into the existing strategy orchestration in SKILL.md.

The key risk is Indeed's aggressive anti-bot posture (Cloudflare, CAPTCHA challenges). Even the user's real Chrome instance may be challenged. Indeed should be positioned as a "best-effort" supplementary source — if CAPTCHA'd, the pipeline skips Indeed and reports the issue, just as it does for cookie expiry on LinkedIn/Wellfound.

v1.2 Congruence: The files modified in this sprint (cdp_search.py, SKILL.md, search-queries.md) overlap with v1.2-database-driven-persistence Phase 1 Sprint 0 (Scraper Skill Update), which cuts over all scraper orchestration from flat files to db/client.py. This sprint is designed to be a tactical addition — it adds Indeed support to the current flat-file system without restructuring the persistence layer. v1.2 Sprint 0 accounts for Indeed in its cutover scope (D8: --api-url flag covers all cdp_search.py subcommands, including the new indeed subcommand). The dependency order is enforced: v1.1 Sprint 3 completes before v1.2 Phase 1 Sprint 0 begins.

Execution Plan

0. Build Indeed CDP Search Client

  1. Task 3.0a: Add search_indeed() to cdp_search.py

    Add an Indeed search function to the CDP client. Indeed's search URL pattern:

    https://www.indeed.com/jobs?q=<keywords>&l=San+Francisco%2C+CA&sc=0kf%3Aexplvl(SENIOR_LEVEL)%3B&sort=date

    Extraction JavaScript (INDEED_EXTRACT_JS): query a[id^="job_"] links from the search results page. For each match, extract the title from the link text, walk up to the parent card/row element, and extract company name and location from adjacent elements. Return a JSON array of {title, company, location, url} objects.

    The function signature mirrors LinkedIn/Wellfound: search_indeed(keywords, count=10). It creates a CDP client, navigates to the search URL with wait_ms=5000 (Indeed is JS-heavy), extracts results, and returns the top count entries.

    CAPTCHA detection: after extraction, if document.title or body text contains "are you a robot", "captcha", "verify you are human", or the URL redirects to a Cloudflare challenge, return an empty array with an error note. Do not retry — Indeed challenges are session-level, not transient.

  2. Task 3.0b: Add indeed CLI subparser

    Add indeed subparser following the same pattern as linkedin:

    • python3 cdp_search.py indeed "senior engineer AI" --count 10 → JSON array of job cards
    • --count defaults to 10, same as other subcommands

    No --experience flag needed — Indeed's explvl(SENIOR_LEVEL) filter is baked into the search URL. No location flag needed — SF Bay Area location is hardcoded (same as LinkedIn).

1. Update SKILL.md for Indeed Strategy

  1. Task 3.1: Add Indeed CDP strategy to SKILL.md Supplementary section

    Add an "Indeed" subsection under "Supplementary strategy: CDP-Driven Authenticated Search" (same level as LinkedIn and Wellfound), containing:

    Prerequisites
    Same Chrome CDP check as LinkedIn/Wellfound. Indeed public search does not require login — no cookie files needed. However, a real Chrome instance is required (Indeed's JS rendering and anti-bot detection make Obscura's bundled Chromium unreliable).
    Usage
    python3 cdp_search.py indeed "<keywords>" --count 10. Returns JSON array of {title, company, location, url} objects.
    CAPTCHA handling
    If the output is empty or contains a "blocked": true field, report: "Indeed blocked (CAPTCHA or anti-bot challenge). Skipping Indeed for this run." Continue with remaining strategies.
  2. Task 3.2: Wire Indeed into unified strategy execution flow

    Update the unified strategy execution order in the Search section:

    1. Board-list search (always runs)
    2. LinkedIn search (if Chrome CDP reachable)
    3. Wellfound search (if Chrome CDP reachable)
    4. Indeed search (if Chrome CDP reachable) — runs last in the CDP sequence, after LinkedIn and Wellfound

    Update the flag detection logic: "fast" (default) includes Indeed. "deep" includes Indeed. No dedicated --indeed flag needed — Indeed is always included when CDP is available, same as the other CDP strategies.

    Update error resilience: if Indeed returns CAPTCHA/blocked, skip Indeed, continue pipeline. Add to Issues section.
